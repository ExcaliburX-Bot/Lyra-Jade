# 技能：X 监测（用 Grok Bot 订阅代替 xAI API）

**什么时候跑**：每天 2 次，北京时间 7:30 和 17:30（在早上、傍晚那两次定时写稿之前）。
**为什么由你做**：Actions 里的「X 监测」走 xAI API，按帖子数计费，已停用。你在 Grok 里本来就能读 X，不额外花钱。
**目标**：把名单账号最近 24 小时里的**正式发布**带进素材库，并把帖子原文存档，让写稿不必再调用 xAI API。
**边界**：只写 data 分支（收件箱、原文存档），可以触发「写稿」。不改文章、代码和名单。每次最多放进 10 条。

## 步骤

1. 同步：`git switch main && git pull -q && git -C data pull -q --rebase`。
2. 读名单 `sources/x-accounts.json`，只看 `"enabled": true` 的组（现在是海外厂商官方号、中国厂商官方号、厂商负责人）。
3. 在 X 上逐个看这些账号最近 24 小时的帖子。**只要正式发布**：新模型、新产品或功能、开源、论文、价格变化、API 变化。跳过转发、回复、活动预告、招聘、梗图、客户案例。
4. 每条要收的帖子，先看它有没有链到官方页面（博客、论文、模型卡、GitHub）：
   - **有官方链接**：打开链接确认是官方原文，用它进收件箱，不用帖子：
     `node scripts/bot.mjs inbox-add --title "<原文标题>" --url "<官方链接>" --tier official --publisher "<厂商>" --published "<原文发布时间>" --source bot:x --category product`
     （论文、模型卡、代码仓库用 `--tier primary`。）
   - **帖子本身就是公告**（没有链接，或链接是视频、图片）：把帖子正文**原样**复制进一个文本文件，作者自己接着发的整串也一起复制，按顺序，每条之间空一行。不要翻译、总结或改写。然后：
     `node scripts/bot.mjs x-add --url "https://x.com/<账号>/status/<ID>" --file /tmp/post.txt`
5. **补读候选里的 X 帖子**：`node scripts/bot.mjs status` 列出的待写候选里，链接是 `x.com/.../status/...`、而 `data/sources/` 里还没有存档的（多半是小互挑中的帖子），照第 4 步的第二种做法存档。
   如果这个候选之前因为「X 帖子读取失败」被跳过，存档后用 `gh workflow run draft.yml -f id=<候选ID>` 让它重写（指定 ID 时不受跳过清单影响）。
6. 推送：`bash scripts/ci/commit-data.sh "bot: X 监测"`。

## 输出

在对话里给出一张表：账号 · 帖子链接 · 收了没有（官方链接 / 帖子存档 / 跳过）· 一句话理由。

## 不要做的

- 不编造帖子、链接或时间；每条都必须是你在 X 上实际打开过的。
- 帖子的发布时间不用填，`x-add` 会从帖子 ID 算出来。
- 名单外账号的帖子可以收，但 `x-add` 会把它记为「线索」（discovery），写稿时必须回到官方原文。不要手动把它改成 `official`。
- 官方链接打开是 401、403、451（例如 OpenAI 博客）：不要绕过，按 AGENTS.md 第 4 节在周报里列出。如果同一件事帖子本身写得完整，可以改用帖子存档（第 4 步的第二种做法）。

## 何时停下

某个账号你在 X 上打不开、被限流，或者一次看到超过 10 条值得收的发布（可能是大事件，需要人来排优先级）：按 AGENTS.md 第 6 节开 Issue。
